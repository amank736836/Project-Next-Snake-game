# BUG-013 — The public write endpoint has no rate limit and no body-size cap

| Field | Value |
| --- | --- |
| Bug ID | `BUG-013` |
| Title | The public write endpoint has no rate limit and no body-size cap |
| Severity | High |
| Priority | P1 |
| Feature | FEAT-007 |
| Environment | production build, demo storage |
| Status | OPEN |

**Preconditions:** Server reachable; any HTTP client.

## Steps to Reproduce

1. Send 50–60 rapid valid submissions and look for back-pressure
2. POST a 1.2 MB JSON body
3. POST a 5 000-character name repeatedly

## Expected

429 after a sensible threshold; 413 for oversized bodies; bounded work per request.

## Actual

All requests succeed (50/50, 60/60). The 1.2 MB body is accepted in ~8 ms. Nothing throttles or caps the endpoint.

## Reproducible

YES (TC-089, TC-089b, TC-120, TC-120b).

## Evidence

`test-results/latest/{api,security}.tap`

## Root Cause

No middleware, edge protection or size check exists in the project; Next.js accepts the body as-is.

## Fix

Rate limit at the edge (per IP and per name) and set a request-body cap; alert on write bursts. Document the cap in the API contract.
