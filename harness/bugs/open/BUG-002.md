# BUG-002 — Foul-word filter matches substrings inside legitimate names and renames them

| Field | Value |
| --- | --- |
| Bug ID | `BUG-002` |
| Title | Foul-word filter matches substrings inside legitimate names and renames them |
| Severity | Medium |
| Priority | P2 |
| Feature | FEAT-007 |
| Environment | production build, demo storage |
| Status | OPEN |

**Preconditions:** Server running; no database required.

## Steps to Reproduce

1. `POST /addScore` with `{"name":"Hancock","score":3}` and read `score.name`
2. Repeat with `Bharat` (contains `rat`) and `Tattaglia` (contains `tatta`)

## Expected

Legitimate names are stored unchanged; only actual profanity is replaced.

## Actual

All three are silently renamed to `Anonymous`; the player is punished for a substring inside their own name, and the rename merges them into the shared Anonymous row (BUG-004).

## Reproducible

YES (TC-060b).

## Evidence

`test-results/latest/api.tap` (TC-060b) · `test-data/edge-cases/edge-case-scores.json`

## Root Cause

`addScore/route.ts` tests membership with `name.toLowerCase().includes(word)` over a 632-entry list, so any substring anywhere in the name matches.

## Fix

Match whole words or token boundaries (split on non-alphanumerics and compare tokens), or keep a curated allow-list for known false positives, with a unit test for the chosen rule.

## Regression Test

TC-060b is today's characterisation; once fixed it becomes `assert.equal(stored.name, "Hancock")`.
