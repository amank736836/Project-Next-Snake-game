# BUG-014 — Internal error details are returned to clients

| Field | Value |
| --- | --- |
| Bug ID | `BUG-014` |
| Title | Internal error details are returned to clients |
| Severity | Medium |
| Priority | P2 |
| Feature | FEAT-007, FEAT-008 |
| Environment | production build, both storage modes |
| Status | OPEN |

**Preconditions:** Server running; one request that fails validation and one with an unreachable database.

## Steps to Reproduce

1. POST `{"score":5}` (no name) and read the response body
2. Call any endpoint against a server with an unreachable `DATABASE_URL`

## Expected

Generic messages for clients, detailed errors in server logs.

## Actual

`{"message":"Cannot read properties of undefined (reading 'toLowerCase')"}` and `{"message":"connect ECONNREFUSED 127.0.0.1:27099"}` are returned verbatim; server-side failures also carry status 400, mislabelling them as client errors.

## Reproducible

YES (TC-061, TC-114, TC-114b).

## Evidence

`test-results/latest/{api,security}.tap` · `evidence/api-responses/RUN-2026-001/addScore-missing-name.body.json` · `evidence/database-results/RUN-2026-001/*-degraded.txt`

## Root Cause

The route's `catch` blocks return `error.message` with a blanket 400.

## Fix

Map known failures to generic messages, log details server-side, return 400 only for client errors and 503 for database unavailability.
