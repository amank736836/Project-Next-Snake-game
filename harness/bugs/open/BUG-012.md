# BUG-012 — The `limit` parameter is unbounded, so the whole board can be pulled in one request

| Field | Value |
| --- | --- |
| Bug ID | `BUG-012` |
| Title | The `limit` parameter is unbounded, so the whole board can be pulled in one request |
| Severity | Low |
| Priority | P3 |
| Feature | FEAT-006 |
| Environment | production build, demo storage |
| Status | OPEN |

**Preconditions:** A board with several rows.

## Steps to Reproduce

1. `GET /highestScore?page=1&limit=100000`
2. Compare the row count with `pagination.total`

## Expected

A documented maximum page size; larger values are clamped or rejected.

## Actual

Every stored row is returned in a single response (TC-079).

## Reproducible

YES (TC-079).

## Evidence

`test-results/latest/api.tap` (TC-079)

## Root Cause

`limit` is parsed and passed to the store's `slice` with no upper bound.

## Fix

Clamp `limit` to a maximum (e.g. 100) or return 400, and document the limit in the API contract.

## Regression Test

TC-079 — convert into a `todo` asserting the cap once the fix is agreed.
