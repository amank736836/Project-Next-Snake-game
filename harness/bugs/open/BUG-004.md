# BUG-004 — Every sanitised submission collapses into one shared `Anonymous` player

| Field | Value |
| --- | --- |
| Bug ID | `BUG-004` |
| Title | Every sanitised submission collapses into one shared `Anonymous` player |
| Severity | Medium |
| Priority | P2 |
| Feature | FEAT-007 |
| Environment | production build, demo storage |
| Status | OPEN |

**Preconditions:** Server running; two different blocked names to submit.

## Steps to Reproduce

1. POST `{"name":"shit","score":50}`
2. POST `{"name":"bitch","score":10}`
3. Read the board and inspect the Anonymous row

## Expected

Unrelated players never share a row; each blocked submission is handled on its own (or is not persisted at all).

## Actual

A single `Anonymous` row holds the highest score from all blocked submissions (50) and accumulates their visits — a blocked name can overwrite another player's best score.

## Reproducible

YES (TC-060c, TC-060d).

## Evidence

`test-results/latest/api.tap` (TC-060c, TC-060d)

## Root Cause

The rename happens *before* the upsert, so every blocked name resolves to the same identity key `Anonymous`.

## Fix

Give anonymised submissions a stable but unique identity (e.g. `Anonymous #a1b2` from a name hash) or store the row with a synthetic id and no name.

## Regression Test

TC-060c (`todo`, asserts one row per blocked submission) and TC-060d (characterisation).
