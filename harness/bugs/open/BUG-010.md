# BUG-010 — Unusable score rows are persisted permanently

| Field | Value |
| --- | --- |
| Bug ID | `BUG-010` |
| Title | Unusable score rows are persisted permanently |
| Severity | Low |
| Priority | P3 |
| Feature | FEAT-008 |
| Environment | production build, demo and MongoDB storage |
| Status | OPEN |

**Preconditions:** A write with a score that is `undefined`, `0` or negative (see BUG-001).

## Steps to Reproduce

1. Upsert `{"name":"Ghost","score":undefined}` in a unit test
2. Read both leaderboards
3. Attempt to find or remove the row through the application

## Expected

Such rows are rejected at the boundary, or are at least purgeable.

## Actual

The row exists in storage forever, is hidden from every read (the `score > 0` filter), and nothing in the product can delete it.

## Reproducible

YES (TC-023).

## Evidence

`test-results/latest/unit.tap` (TC-023)

## Root Cause

The store writes whatever it receives and filters only at read time; the demo store has no cleanup path and the API offers no delete.

## Fix

Reject invalid writes (BUG-001) and add a maintenance path (script or admin-only cleanup) for rows that fail the new rules.

## Regression Test

TC-023 characterises today's behaviour; after the fix it should assert the row is absent.
