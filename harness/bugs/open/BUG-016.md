# BUG-016 — Scores are unauthenticated and unverifiable, so any client can top the board

| Field | Value |
| --- | --- |
| Bug ID | `BUG-016` |
| Title | Scores are unauthenticated and unverifiable, so any client can top the board |
| Severity | High |
| Priority | P1 |
| Feature | FEAT-007 |
| Environment | production build, demo storage |
| Status | OPEN |

**Preconditions:** Server reachable; the current top score can be read publicly.

## Steps to Reproduce

1. Read the top score from `/highestScore`
2. POST `top + 1` for a new name
3. Read the board again

## Expected

Implausible submissions are rejected, or the leaderboard is understood and documented as decorative.

## Actual

The forged score lands in rank 1 immediately (TC-119b). There is no plausibility check, no session and no signature.

## Reproducible

YES (TC-119, TC-119b).

## Evidence

`test-results/latest/security.tap` (TC-119, TC-119b)

## Root Cause

The endpoint is public by design; the only input-level defence is the foul-word filter.

## Fix

Choose deliberately: (a) treat the board as decorative and document it, plus rate limits (BUG-013); or (b) add server-side plausibility (max points per second, monotonic growth) and/or signed run tokens.

## Regression Test

TC-119 (`todo`) — it stays red until a defence is chosen and implemented.
