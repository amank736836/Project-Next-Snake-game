# BUG-015 — No security headers are configured and the framework is advertised

| Field | Value |
| --- | --- |
| Bug ID | `BUG-015` |
| Title | No security headers are configured and the framework is advertised |
| Severity | Medium |
| Priority | P2 |
| Feature | FEAT-012 |
| Environment | production build, all routes |
| Status | OPEN |

**Preconditions:** Server reachable.

## Steps to Reproduce

1. Inspect the response headers of `/` and of the API endpoints
2. Look for CSP, `X-Content-Type-Options`, `Referrer-Policy`, frame protection and HSTS
3. Check `X-Powered-By`

## Expected

The standard hardening set is present and the framework is not fingerprinted.

## Actual

None of the security headers are sent; `X-Powered-By: Next.js` is.

## Reproducible

YES (TC-110, TC-110b, TC-111).

## Evidence

`test-results/latest/security.tap` · `evidence/api-responses/RUN-2026-001/page-shell.headers.txt`

## Root Cause

No `headers()` configuration in `next.config.ts` and no edge/CDN configuration in the repository.

## Fix

Add the headers (or set them at the CDN/edge) and set `poweredByHeader: false`.
