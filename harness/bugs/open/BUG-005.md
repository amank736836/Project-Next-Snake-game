# BUG-005 — Invalid page/limit values are not validated: nulls are echoed and NaN silently empties the board

| Field | Value |
| --- | --- |
| Bug ID | `BUG-005` |
| Title | Invalid page/limit values are not validated: nulls are echoed and NaN silently empties the board |
| Severity | Low |
| Priority | P3 |
| Feature | FEAT-006 |
| Environment | production build, demo storage |
| Status | OPEN |

**Preconditions:** Non-empty board.

## Steps to Reproduce

1. `GET /highestScore?page=abc&limit=5`
2. `GET /highestScore?page=1&limit=abc`
3. `GET /highestScore?page=1&limit=0`
4. Call `listHighest(NaN, 5)` directly (unit)

## Expected

400, or coercion to the documented defaults (page 1, limit 5) with coherent metadata.

## Actual

`page: null` / `limit: null` / `totalPages: null` are returned inside a 200 response; `NaN` reaches the store and returns an empty array with a non-zero `total`.

## Reproducible

YES (TC-024, TC-078, TC-078b).

## Evidence

`test-results/latest/{api,unit}.tap` · `evidence/api-responses/RUN-2026-001/highestScore-invalid-page.body.json`

## Root Cause

`parseInt()` results are used without validation in `highestScore/route.ts` and passed into the store's slicing arithmetic.

## Fix

Validate both parameters (`Number.isInteger(p) && p >= 1`; `limit` clamped to a documented maximum), otherwise 400.

## Regression Test

TC-078 (`todo`) plus TC-024 and TC-078b as characterisations.
