**Preconditions:** A reachable MongoDB instance and two concurrent first submissions for one name.

## Steps to Reproduce

1. Set `HARNESS_MONGODB_URL` and run `npm run test:database`
2. TC-135 fires 10 parallel first-time writes for one name
3. Count the documents returned for that name

## Expected

Exactly one document: the write path is atomic (unique index on `name`, or an upsert with `$max`/`$inc`).

## Actual

NOT EXECUTED — no MongoDB available. Code inspection shows `findOne` followed by `save` with no unique index on `name`, so a race is possible.

## Reproducible

UNKNOWN — requires the database run (`UNKNOWN / REQUIRES VALIDATION`).

## Evidence

none yet — blocked (see `test-tools/mongodb-local.md`)

## Root Cause

`addScore/route.ts` (MongoDB branch) does a non-atomic read-then-write; `Score.ts` declares no unique index.

## Fix

Add `unique: true` to the `name` index and use `findOneAndUpdate` with `$max`/`$inc`/`$setOnInsert`, handling duplicate-key errors.
