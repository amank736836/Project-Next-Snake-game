# BUG-001 — Non-numeric or missing scores are accepted and stored

| Field | Value |
| --- | --- |
| Bug ID | `BUG-001` |
| Title | Non-numeric or missing scores are accepted and stored |
| Severity | Medium |
| Priority | P2 |
| Feature | FEAT-007 |
| Environment | production build, demo storage (MongoDB coerces the string through a cast) |
| Status | OPEN |

**Preconditions:** Any HTTP client can reach the endpoint; no database required.

## Steps to Reproduce

1. `POST /api/snakeGame/addScore` with `{"name":"NoScore"}` → observe 201
2. POST with `{"name":"StrScore","score":"7"}` → observe 201
3. POST with `{"name":"ObjScore","score":{"$ne":1}}` → observe 201
4. Read the board and search for the three names

## Expected

400 for a missing or non-numeric score; every stored row has an integer score ≥ 0.

## Actual

All three return 201. Rows are stored with `undefined`, `"7"` and an object value; none can ever appear on a leaderboard, and string scores break numeric ordering if the board is sorted in the client.

## Reproducible

YES — deterministic, on every run (TC-067, TC-068).

## Evidence

`test-results/latest/api.tap` (TC-067, TC-068) · `test-cases/score-api/negative.md`

## Root Cause

`src/app/api/snakeGame/addScore/route.ts` destructures the JSON body and passes it to the store with no schema; the in-memory store writes whatever it receives.

## Fix

Validate the payload (`Number.isInteger(score) && score >= 0`, plus a plausibility cap) before writing, and return 400 with a generic message. Reuse the same validator in the MongoDB path.

## Regression Test

TC-067 and TC-068, written as `todo` tests asserting the 400. They flip to green when the fix lands.
